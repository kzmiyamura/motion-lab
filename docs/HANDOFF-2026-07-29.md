## 1. プロジェクトの全体像（5行で）

- HOMEタブのフォルダ毎に**解析指示書（MD）**を持たせ、動画投入で自動解析するパイプラインを構築中

- 設計書: `docs/folder-analysis-design.md`（基本）・`docs/folder-analysis-detailed-design.md`（詳細）
- ThinkCentre（Windows・CPU・自宅サーバー `server/`）が実行基盤。Mac側とは `server/CLAUDE.md`（指示）⇄ `server/REPORT_FROM_THINKCENTRE.md` + `server/NOTES_TO_MAC_CLAUDE.md`（報告・申し送り）の**ファイル経由で連携**（git push/pull）
- ユーザーは実装フェーズを P0（配管）→ P1（CV計測）→ P2（Claude裁定）の順で進めることを承認済み

## 3. 【最重要】直近の発見: MediaPipe が本質的ボトルネック → YOLO-pose へ移行すべき

検証動画 `2fda2815-2073-4cd6-94d5-3d9dca9108ce`（Lewis Barr On2、Instagram画面録画、31.5秒、
背景の鏡に撮影者が写り込み・密着オクルージョン多）での実測:

| 検出器 | 2人同時検出 | 備考 |
|---|---|---|
| MediaPipe Heavy (num_poses=4 + ROIマスク) | **12/315 (4%)** | 密着ペアを1人に潰す。ユーザーも動画を見て「全くダメ」と評価 |
| **YOLOv8s-pose（プロトタイプ）** | **283/315 (89%)** | 鏡の撮影者も検出→bbox面積フィルタで正しく除外（赤枠）。SHR2D も男1.59 > 女1.44 と正しい方向 |

- プロトタイプ: `server/analysis/prototype_yolo_pose.py`（動作確認済み。10fps間引き・面積上位2人・SHR2D・デバッグ動画出力）
- 比較動画をユーザーのデスクトップに保存済み: `背景マスク確認_salsa_debug.mp4`（MediaPipe+ROI版）と `YOLO検出比較_salsa_debug.mp4`（YOLO版）。ユーザーはMediaPipe版を見て不満、YOLO版を見せた直後にセッション交代
- **次セッションの本命タスク: `analyze_pair.py` の検出器を YOLO-pose に置き換える（または YOLO検出→MediaPipe crop のハイブリッド）**

### YOLO統合の設計メモ
- `pip install ultralytics`、モデル `yolov8s-pose.pt`（22MB、初回自動DL。**破損DLに注意** — 後述）
- COCO 17キーポイント: 肩=5,6 / 腰=11,12。**z が無い**ので SHR は 2D になる
  - 選択肢A: YOLO単独（SHR2D。横向きで劣化するが検出率89%の価値が圧倒的）
  - 選択肢B: YOLOで人物bbox → 各crop に MediaPipe 単人数(Heavy) → 33点+z で SHR3D（precision最高・処理2倍）
  - 推奨: まず A で全面置き換え→精度不足なら B。ユーザーの方針は「まずJS/CV計算を頑張らせ、Claude利用は最小から段階的に」（設計書§1.4）
- 既存の ROIマスク・pick_main_pair（面積上位2）・high/low分離verdict・contested抽出・デバッグ動画のロジックはそのまま流用可能
- Instagram画面録画のUI（再生ボタン等）が被っても YOLO はほぼ影響を受けていなかった

## 6. 環境の落とし穴（次セッションがハマらないために）

| 罠 | 対処 |
|---|---|
| Mac の `python3` は Xcode 3.9 | venv作成はそれでOKだが、**`timeout` コマンド(x86_64)経由で実行すると universal binary が x86_64 で起動し arm64 wheel と不整合**になる。timeoutラッパーを使わない |
| Mac の nvm デフォルト Node 20 に `node:sqlite` が無い | サーバーのローカル起動は `~/.nvm/versions/node/v24.18.0/bin/node` を使う |
| github.com への接続が時々タイムアウト | push失敗したらリトライで通る。ultralyticsモデルDLも**破損したら削除して再DL**（破損ptはローカルで謎ハングを起こした） |
| scratchpad はセッション毎に消える | venv・検証動画は次セッションで作り直し。動画DL: `ffmpeg -i "https://motion-lab-apa.pages.dev/relay/hls/<id>/playlist.m3u8" -c copy local.mp4`（ffmpegは `server/node_modules/ffmpeg-static/ffmpeg`） |
| サーバーESM | server/ は NodeNext。import は `.js` 拡張子必須 |
