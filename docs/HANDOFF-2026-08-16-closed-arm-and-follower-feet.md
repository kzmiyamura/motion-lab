## 0. この日いちばん効いた教訓

**「腕が届かない」「足がずれる」は、目で見て推測せず寸法で確定させる。**
今回の原因はすべて数字で一意に決まった:

- 手が背中に回らない → 肩から的まで **0.775m**、腕は **0.522m**。25cm 足りない
- 女がジャンプ → 支持脚の伸びが **6.5cm / 0.98cm per frame**（男は 3.0cm / 0.14）
- 足が重心の下に無い → 足の中点が体の **15.8cm 前**（男は 4.9cm）
- 3 の位置 → **2 より 24cm 後ろ**に落ちていた

計測はヘッドレスの使い捨てテストで取れる（`src/__tests__/tmp-*.test.ts` を作って
`npx vitest run` → 消す）。three.js はそのまま node で動くので、リグを組んで
IK を通し、手首のワールド座標や胴体円柱への食い込みまで測れる。

**もうひとつの教訓（叱られた点）**:
- **合格済みのものを触らない。** 男の足は毎回「差分 0.0cm」を計測してから出す。
  良かれと思って男にも同じ修正を当てると 15〜19cm 動いてしまう
- **言われたカウントだけ直す。** 3 を直すよう言われて 7 も対称に直したら怒られた

## 1. クローズドポジション — 手が背中に回っていなかった

### 原因（2つ重なっていた）

1. **ペア距離の下限に押し戻されていた**
   `CoupleFigure.tsx` の `PAIR_MIN = 0.58` は、動画解析で2人が重なって距離が 0 に
   潰れるのを防ぐための下限。これが手描きクリップにも無条件にかかり、
   クローズドの振付値 **0.30m を 0.58m に押し戻していた**。
   結果、男の右肩→女の背中が 0.775m になり、腕 0.522m では届かず、
   `clampToArm` が手を切り詰めて **女の腹の前（25cm 手前）で停止**していた。
2. 的が「背中の真後ろ」で、肩から一直線に伸び切っていた

### 直し方

- `pairFloorAt(clip, t)`: 手描きクリップ（`armTimeline.source === 'scripted'`）の
  **closed 区間だけ** 下限を `PAIR_MIN_CLOSED = 0.20` に落とす。
  CBL の通り抜け・ベーシックの片手・動画クリップは従来どおり 0.58
  - **注意**: CBL の authored 距離は 0.404〜0.671 で、通り抜けは元から下限に
    かかっている。ここを緩めると合格済みの CBL の見た目が変わる
- `CLOSED_HALF_GAP` 0.15 → **0.185**（ユーザー指示「10センチほど離していい」）。
  胴体カプセルの半径 0.135 なので 0.37 - 0.27 = **隙間 10cm**
- 届かないぶんは **肩を前へ出して**補う（`CLOSED_SHO_FWD = 0.08`＝肩甲骨の外転）。
  距離を詰めて解決してはいけない（前回それで却下された）
- 的は `CLOSED_BACK_R = 0.195` / `CLOSED_BACK_ANG = 40°`（女の腰中点から見た極座標）。
  **見えている胴の外側**に取る。内側だと手が体の中で止まる

### 実測（合格ライン）

```
体の隙間 = 0.100m      肩から的 = 0.471m（腕 0.522m・切り詰めなし）
肘角     = 64°         手首は女の背面より 2.2cm 奥・体から 6cm 外
貫通     = 上腕 -0.071 / 前腕 -0.008（どちらも体の外）
```

調整するならこの順:
背中への回り込みが足りない → `CLOSED_BACK_R` を上げる /
肩が前に出すぎ → `CLOSED_SHO_FWD` を下げる（下げたぶん腕は伸び切る）

### ついでに直した潜在バグ

`solve2Bone` に `target.z` を渡していた（肩ローカル z を引いていない）。
肩の z が常に 0 だったので今まで無害だったが、肩を前へ出すと手が 8cm 奥へ行き過ぎる。

## 2. CBL の女がジャンプして見えた

**原因**: 踵が下りると足首が `HEEL_DROP = 3.5cm` 沈む。男は腰も同じだけ沈めてある
（`hy - HEEL_DROP * max(heelL, heelR)`）が、**女の腰は `hy - 0.04` の固定値**だった。
腰が動かないまま足首だけ上下する ＝ 支持脚だけが伸び縮みする ＝ 体が跳ねて見える。

| | 支持脚の伸びの幅 | 1フレームの変化 |
|---|---|---|
| 男（合格済み） | 3.0cm | 0.14cm/f |
| 女 修正前 | 6.5cm | **0.98cm/f**（男の7倍） |
| 女 修正後 | 3.0cm | 0.14cm/f |

**直し方**: 女の腰にも同じ沈み込みを入れる。女の踵は男の鏡（4=右・8=左）なので
`Math.max(cblHeelAt('L', beat, true), cblHeelAt('R', beat, true))` を使う。

## 3. 女の足が重心の下に無かった

**原因**: On2 の着地基準は「腰の真下」ではなく**腰の揺れの中心**（重心自身が ±0.175
揺れるため、揺れる腰を基準にすると歩幅が二重に相殺される）。その中心を
**小節ごとの固定平均**で取っていた。その場で揺れているだけの男には正しいが、
**小節の中で移動する女**（男を追い越す）には合わず、移動したぶん足が置き去りになる。

**直し方**: 女だけ「**その歩の拍を中心にした 8 拍（揺れ1周期）の移動平均**」にする
（`swayCenter()` の `mirror ? ... : ...`）。線形に進む区間では中心平均は
その拍の値と一致するので、移動をそのまま追える。

**男には当てない** — 当てると足が最大 19.4cm 動く（合格済みなので触らない）。

| | 足の中点の腰からのズレ（符号つき平均） |
|---|---|
| 男（合格済み） | 4.9cm |
| 女 修正前 | 15.8cm |
| 女 修正後 | 2.5cm |

## 4. On2 の女のカウント3の位置

**結論（ユーザー指示・3回言われた）**:
**3 の足は 2 の足のもう少し前に置く。1・2・3 は共々前に出す。**

鏡は `fwd` を一律反転していたので、女の 3 が `-0.01` になり、
2（+0.35）より **24cm 後ろ**に落ちていた。

```
女の fwd:  1 = +0.05 → 2 = +0.35 → 3 = +0.41（= 2 の QUARTER 前）
           5・6・7 と 1・2 は鏡のまま。**3 以外は触らない**（7 = +0.01 のまま）
```

実測（体の向きに射影した、直前に踏んだ足からの距離）:
`1→2: +48.8cm / 2→3: +18.7cm`（どちらも前へ）

**途中で2回外した記録**（同じ失敗を繰り返さないために残す）:
1. 「3 = 1 の靴1/4前（+0.11）」→ 2 より後ろのまま。**基準は 1 ではなく 2**
2. 「3・7 を直前の着地から測り直す」後処理 → 移動ぶんまで消えて足が体の下から外れた
   （両足が同じ側に揃う割合が 13% → 25%）。この後処理は削除済み

## 5. CBL On1 の女に足を焼き込んだ

**原因**: On1 の女だけ足を焼き込んでいなかった（`placeJoints` に feet を渡さない＝
`v[LANK]=0`）。足のデータが無いとリグ側が拍ごとに足を出し続けるので、
**振付に 4・8 の歩が無いことを知らず、休めない**。

**直し方**: `landsF = cblLandings(KEY_F, timing, true)` を On1 でも作る。
振付の歩は 1・2・3・5・6・7 だけなので 4・8 は自動的に休みになり、
5・1 へ向かう歩は `charge`（ため）なので 4・8 はほぼ静止 → AND で放つ形になる。

実測（拍の前後 0.4 拍での足の移動、通り抜け以外の 4・8）:
男 7〜8cm / 女 7〜9cm で一致。拍 12・16・28 は通り抜けの最中なので男女とも動く。

**On1 の女は見た目が大きく変わる**（手続き生成 → 振付ベース）。要確認。
