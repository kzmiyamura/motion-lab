## 1. 今回入れたもの（未コミット・**未確認**）

### (a) 支えの拘束 — 女の重心が足で支えられる（`clampToSupport()`）

**指摘**: 「on2 CBL の女性が後ろ足体重で、足が重心に対して前に出すぎ。
どんなときでも重心を支えられる形にして」。**方式は A（拘束を後がけ）でユーザー合意済み。**

着地の瞬間に「腰より後ろの足」が1本も無い拍だけ、**いま置く足を後ろへ引く**。
足りている拍は 1mm も動かさない。引く量は次を全部満たす範囲まで 1cm ずつ譲る:

- **膝が裏返らない**: 足が床にある**間ずっと**腰〜足首を見て、**補正前の最大を超えない**
  （着地時だけ見ると、腰が進む途中で伸び切る。実際これで 88.0 → 92.1cm に悪化させた）
- **自分の足と重ならない**（8cm）/ **相手の足を踏まない**（12cm）。
  どちらも**運んでいる途中の軌跡**込みで見る（着地点どうしだけでは遊脚のすれ違いを見落とす）

実測（CBL On2・32拍を 0.25拍刻み）:

| | 補正前 | 補正後 |
|---|---|---|
| 両足とも腰より前（＝支えなし） | 33% | **27%**（男は 25%） |
| 脚の最大の伸び | 88.0cm | 88.0cm（変化なし） |
| 相手の足との最小距離 | 12.3cm | 12.3cm（変化なし） |
| 自分の両足の最小距離 | 9.4cm | 9.4cm（変化なし） |
| 男の関節 | — | **差分 0.0cm** |

残る 27% は通り抜けで実際に移動している最中で、歩行では重心が足より前に出るのが普通。
合格済みの男が 25% なので同水準。

### (b) クローズドの手が相手にめり込む（`place(..., avoid)`）

**指摘**: 「手がめり込んでるやんけ」。

**原因**: クローズドは腰の間隔 0.37m、相手の胴半径 0.17m
→ **相手の体の表面は自分の中心から 0.20m**。フォロワーのニュートラルの手は体の前 0.30m
なので **10cm 相手の胸に入る**。しかも**レイヤー3.6（クローズドの手）だけ胴体回避を
通していなかった**（他の腕は全部 `pushOutOfTorso`/`routeAroundTorso` を通っている）。

**直し方**: フォロワーの手に他と同じ胴体回避を通した。
**リーダーの背中へ回す手は避けさせない** — あれは相手を回り込むのが目的で、
避けさせると背中に届かない（前回それで失敗している）。

### (c) 「送り出される3」だけ前に出す（コミット済み `8eb0af9`）

女が通り抜けるのは**拍 1〜4 と 17〜20**（腰の移動 30〜45cm/拍 で実測）。
よって送り出される 3 は **拍 3・19**、CBL に入る前の 3 は **拍 11・27**。
後者は鏡のままへ戻した。**最初 bar の偶奇を逆に書いていて、測って気づいた。**

## 2. 未着手（**次はここから**）

### (A) 通り抜けで、女のリードされている手が自分の胸に貼り付く ← 最優先

**指摘**: 「CBL の反対側へ女性が行くとき、リードされてる方の手が不自然に自分の胸にぺったりくっつく」。

**原因（コードと寸法で特定済み）**: つないだ手は「2人の肩の中点、そこから 20cm 下」。
通り抜け中はすれ違うので**中点が彼女の体の中に入り**、そのあと胴体回避が働いて
**胴の表面（0.17m）まで押し出されて止まる**。押し出しは「中に入れない」だけで
「体から離す」処理ではないため、胸に貼り付いた位置に落ち着く。

**提案（ユーザーの返事待ち。まだ何も変更していない）**:
通り抜けの間（`prep`/`pass`/`close`）だけ、つないだ手の**彼女からの最小距離を
「胴の表面」ではなく「胴＋手のぶん」＝ 0.17 → 0.27m** にする。
実装したら測って報告する数字は、通り抜け中の「手と彼女の体の中心軸との距離」の最小値
（いま 0.17 → 0.27）、肩から手 ≤ 0.52m（腕が伸び切らない）、男の差分 0.0cm。

### (B) CBL のベーシック区間に、CBL 用の足の置き方が入っている

**指摘**: 「CBL で足の付く位置を変えるのを、ベーシックのときに入れちゃだめ。
ベーシックのときの動きをしないと」。**方針の確認待ちで止めている。**

実測（CBL クリップのベーシック区間 vs ベーシッククリップ・On2）:

| | ベーシック | CBL のベーシック区間 | ずれ |
|---|---|---|---|
| スタンス幅（横） | **9.0cm** | **11.3〜14.7cm** | 常時 2〜6cm 広い |
| 前後の踏み出し | 男 2拍 −17.5cm | −23.0cm | 各拍 2〜8cm |
| ループの継ぎ目（拍0・7） | — | — | 最大 17〜21cm |

原因は定数レベルで判明:
1. スタンス幅が別物 — ベーシック `FOOT_LATERAL = 0.09` / CBL `CBL_LATERAL = 0.13`
   （「ベーシックの 0.09 では狭い」という過去の指摘で広げた経緯がある）
2. 踏み出しの基準が別物 — ベーシックは体ローカルのキー（`basicFootKeys`）、
   CBL はワールドの着地点（`cblLandings`）
3. On1 は差がさらに大きい（CBL On1 の踏み出し 0.14/0.12 vs ベーシック On1 の 0.28）

**ユーザーに確認すべきこと（1つだけ）**: ベーシックの8拍を「ベーシッククリップと完全に同じ足」に
戻す、という理解で合っているか。その場合**スタンス幅も 0.09 に戻る**ので、
CBL の8拍（0.13）との間で歩くたびに幅が変わって見える可能性がある。

## 3. 「変わっていない気がする」問題（前回からの持ち越し・切り分け途中）

ニュートラルを胸の高さへ上げたあと「何も変わっていない気がする」と言われた。
確認できたのは**dev サーバー（5173・5174 の両方）が新しい値を配信している**ところまで:

```
curl -s http://localhost:5173/src/engine/armPose.ts | grep NEUTRAL_HAND
→ export const NEUTRAL_HAND = [0.13, -0.1, 0.3];
```

残る可能性は3つ。**この切り分けから再開する**:
1. ブラウザが古いモジュールを掴んでいる → 強制リロード（Ctrl+Shift+R）
2. 見ていたのがリーダー側 → 変えたのはフォロワーだけ
3. フォロワーの空き手が想定した経路（レイヤー4 の `d === 1` 分岐）で動いていない
   → その場合は理解が間違い。`?armDump=<秒>,<秒>` で手首・肘の実座標を出して**測ってから**直す
