# 腕の状態機械 — 設計（2026-08-13）

`docs/arm-motion-policy.md` で合意した方針（腕は復元せず、役割と拍から決める）の実装設計。
前提はカメラ1台。方針を変えるときはユーザーに諮る。

## 全体像

```
オフライン（動画1本につき一度）                実行時（ブラウザ・決定的）
┌──────────────────────────┐      ┌──────────────────────────────┐
│ 幾何パス（自動）              │      │ ArmTimeline を時刻で引く        │
│  events + 動線 + 肩線から     │      │   ↓                          │
│  腕タイムラインの下書きを生成    │      │ 状態 × 拍位相 → 手の目標点      │
│      ↓                     │      │ （体格・実測root/yawで具体化）    │
│ Claude パス（曖昧区間のみ）    │ JSON │   ↓                          │
│  元動画のフレームを見て確定     │ ───→ │ 胴体回避（既存 route/pushOut）  │
│      ↓                     │      │   ↓                          │
│ 検証パス（自動）              │      │ 2ボーンIK（既存 solve2Bone）    │
│  動線・距離・ヨーで裏を取る     │      │ 手首実観測は数cmの最終補正のみ    │
└──────────────────────────┘      └──────────────────────────────┘
```

- 実行時に LLM・確率的推定は入れない。クリップに同梱した `armTimeline` を再生するだけ
- 現行のレイヤー3（つなぎ腕）・レイヤー4（フリー腕）は、このタイムラインを目標生成器に
  差し替える。胴体回避・IK・肩甲上腕リズムはそのまま使う（f4071e2 で実測クリーン）

## 状態の定義

### リーダーの各手（左右が独立に持つ）

| 状態 | パラメータ | 手の目標（リーダーローカル） |
|---|---|---|
| `free` | — | 体側ニュートラル（現行レイヤー4の構え） |
| `hold` | フォロワーの手（L/R） | 共有ホールド点（現行レイヤー3の中点則） |
| `prep` | 回す向き（CW/CCW） | ホールド点を回す向きと逆へ 10–15cm 引く |
| `lead_turn` | 向き・回転数・高さ | フォロワーの回転軸の真上（現行 turner lift の一般化） |
| `open_break` | — | ほぼ水平に前へ。距離の伸縮に追従 |
| `back_support` | — | フォロワー背面、胴体の高さ |

フォロワーの手は鏡像で決まる: リーダーが `hold` ならフォロワーの対応手も `hold`（同じ共有点）、
リーダーが `lead_turn` ならフォロワーの手は頭上の共有点へ。フォロワー独自の状態は持たない
（サルサの構造上、フォロワーの腕はリードへの応答。シャイン区間だけ両者 `free`）。

`hammerlock`（片腕を背中へ回して固定）は**ある**（ユーザー確認済み）ので v1 の状態に含める:

| 状態 | パラメータ | 手の目標 |
|---|---|---|
| `hammerlock` | どちらの腕を背中へ | フォロワー背面・腰の高さ。肘は鋭角（<70°は警告域） |

シャイン（手を離して別々に踊る区間）も**あり得る**（同）: 両者とも `free` の区間として表す。
専用状態は足さず「hold が無い区間が数拍続く」＝シャインと解釈する。

### 時間の文法（技イベント → フェーズ列）

イベント（`clip.events`）と拍（`clip.beatGrid`）から決定的に展開する。
逆順・飛び越しは起きない（方針文書どおり）。

```
Turn(by=follower, rotations=N):
  prep      : ev.t − 2拍 〜 ev.t − 0.5拍   … 手は逆へ溜める
              ※ prep は「女性にプレパレーションを取らせるための男性の手のリード」
                （ユーザー確認済み）。2拍前で正しい。On1/On2 でタイミングが違うので、
                クリップがどちらで踊られているかをオフラインで判定して拍を合わせる
                （ブレイクが1拍目か2拍目か＝足首の最大変位の拍位置で読める）
  initiate  : ev.t − 0.5拍 〜 ev.t + 0.5拍  … 手を頭上へ導く
  rotate    : 〜 ev.t + N×2拍              … 回転軸の真上を維持
  settle    : 〜 +1拍                      … hold へ滑らかに戻す

CBL(by=pair):
  open      : ev.t − 1拍 〜 ev.t           … リーダー半歩引いて道を開ける
  pass      : ev.t 〜 ev.t + 2拍           … フォロワー通過。手は頭上ではなく
                                             **右手=フォロワーの背中（back_support）、
                                             左手=胸の高さでキープ（hold）**が一般的
                                             （ユーザー確認済み。頭上を通す想定は却下）
  close     : 〜 +1拍                      … 180°入れ替わった向きで hold へ

イベントなし区間:
  距離 ≤ 腕リーチ → hold ／ 超えたら free
  距離が拍同期で伸縮（±10cm 以上、1・5拍目で最遠）→ open_break
```

フェーズ長の初期値は上記。実測（3本51イベント）で拍に合わせて調整する。

## つないでいる手の決定（記録の hold は使わない）

実測で `hold`/`hold2d` は18件中一致0件なので**入力として捨てる**。幾何から決める:

1. **通過側**: 技の前後でリーダー正面（肩線の法線＋鼻）に対するフォロワーの左右符号を取る
   （実測済み: 符号ははっきり反転する）
2. **手の対応則**: フォロワーが右へ通過 → リーダー右手 × フォロワー左手。左は鏡像。
   その場ターン（符号が反転しない）→ 直前の hold を維持
3. **連続性制約**: 手の切り替えは技の境界（settle/close フェーズ）でのみ起こす。
   技の途中で手は替わらない（物理的に替えられない）

実測5例のうち2例はこの規則と記録が食い違うが、食い違っているのは記録側と考える
（方針文書の判断）。Claude パスで元動画を見て最終確定する。

## オクルージョン区間の扱い

- 区間の判定は既存の考え方（肩幅・足首Y・Z → 手前判定）をオフライン側で流用
- **フォロワーが手前**: 観測を信じてタイムラインをそのまま進める
- **リーダーが手前（フォロワー不可視）**: タイムラインは「入る前の状態 → 出た後の状態」を
  繋ぐ唯一のサルサ的経路で埋める。回転数と手の辻褄が合わない場合のみ Claude パスに回す
- 実行時は区別しない。オフラインで確定済みのタイムラインを再生するだけ

## ArmTimeline スキーマ（クリップに同梱）

```jsonc
{
  "armTimeline": {
    "version": 1,
    "source": "geometry | claude | mixed",   // どのパスで確定したか
    "segments": [
      {
        "t0": 3.05, "t1": 3.55,
        "leader": { "L": "hold", "R": "prep" },
        "follower": { "L": "free", "R": "hold" },
        "hold": { "leader": "R", "follower": "L" },  // つなぎの対応（null = 離れている）
        "phase": "prep",              // 上の文法のどのフェーズか
        "turn": { "dir": "CW", "rotations": 1 },     // lead_turn 系のみ
        "passSide": "right",          // CBL/移動ターンのみ
        "confidence": "observed | inferred"  // 観測で裏が取れたか、穴埋めか
      }
    ]
  }
}
```

- セグメントは連続・非重複。実行時は二分探索＋前回カーソルで O(1) 参照
- `confidence: inferred` はデバッグ表示で区別できるようにする（推測区間の可視化）

## 実行時の目標生成（CoupleFigure の差し替え範囲）

差し替えるのは「手の目標点をどこに置くか」だけ。以降のパイプラインは既存を使う。

| 今 | 後 |
|---|---|
| holds = buildHolds(clip) ← 記録の hold | armTimeline のセグメント参照 |
| linked 判定＝hold 文字列 | セグメントの `hold` フィールド |
| turner/lift = events を毎フレーム走査 | セグメントの `phase`/`turn`（走査不要になる） |
| フリー腕＝手首実観測へ IK | 状態別の手続き目標。実観測は w が高いときに数cm寄せるだけ |

目標点は**カップルローカル座標**（リーダー正面基準）で状態ごとにパラメトリックに定義し、
実測の root 位置・yaw・体格（SHO_DY 等）で具体化する。拍位相（beatGrid）で補間を駆動する。

## 検証（数字で前後比較）

1. **破綻率**: `__armProbe = 1` の「仰角>100°かつ肘が背中側」発生率。導入前の値を先に取る
2. **貫通**: `?armDump=0,99` の depth>0 発生率（f4071e2 の実測器をそのまま使う）
3. **手の一致**: 幾何で決めた hold と Claude が絵を見て決めた hold の一致率
   （18件で照合。ここが低ければ幾何ルールの側を直す）
4. **見た目**: `compare_frames.py`（要再作成）で元動画と3Dを並べ、技5例をユーザーが確認

## 実装順序

1. オフライン幾何パス（server/analysis に Python）: 3本のクリップに armTimeline を生成。
   通過側・hold 決定・フェーズ展開まで。`confidence` を付ける
2. 検証3（Claude が元動画キーフレームで hold を目視確定）→ 幾何ルールとの一致率を測る
3. CoupleFigure の目標生成器を差し替え（armTimeline があるときだけ新経路、無ければ現行）
4. 検証1・2の前後比較 → ユーザーが本番で技5例を確認
5. 合格したら現行の buildHolds / events 走査を削除

## 拍格子の実情（2026-08-13 実測）

幾何パスは `events × beatGrid` から時刻を決めるので、拍が無いと文法が引けない。

| クリップ | 音声 | beatGrid |
|---|---|---|
| 2fda2815（ターン主体・縦） | 有り（rms 0.137） | 172.3bpm・conf 0.285（音声由来） |
| 8c312c6d（推奨条件・横） | **ほぼ無音**（rms 0.0014） | **無し** |
| bb0efcb9（引き・横） | **ほぼ無音**（rms 0.0013） | **無し** |

**動き（足首速度）からの拍推定は採らない。** 実装して測ったところ、自己相関の山は拍ではなく
小節（1.70s）に立ち、4で割り戻しても 141bpm。音声真値のある 2fda2815 で **22% ずれた**。
無音クリップは `--bpm=<値>` で外から拍を与える（`beatgrid_from_bpm`・`source: given`）。
腕の文法は全て「イベント時刻 ± k拍」の相対量なので、必要なのは拍の長さだけで位相は要らない。

On1/On2 判定も、格子の位相が決まらない以上「8拍に畳んだブレイクの偏り」しか見えない。
偶然水準（2/8 = 0.25）を明確に超えないときは `unknown` を返す（2fda2815 は 0.26 = 判定不能）。

## ユーザー確認済み（2026-08-13）

1. **prep = 2拍前で正しい**。実体は「女性にプレパレーションを取らせるための男性の手のリード」。
   On1/On2 でタイミングが違う → クリップの On1/On2 判定をオフラインパスに追加
2. **CBL**: 右手はフォロワーの背中、左手は胸の高さでキープが一般的。頭上は通さない
3. **ハンマーロックはある** → v1 の状態に含めた
4. **シャインもあり得る** → 「hold の無い区間が続く」として表現（専用状態なし）
