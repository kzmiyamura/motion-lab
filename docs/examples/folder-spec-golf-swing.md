# ゴルフのスイングの解析

## 目的
ゴルファー 1 人のスイングを、横（飛球線の後ろ）または正面から撮った動画で、
フォームの崩れと再現性を、本人が次の練習で直せる形で伝える。

## 見る観点
- アドレス: 足幅、膝の曲がり、前傾、頭の位置。構えが毎回同じか
- テークバック〜トップ: 体の回転量（肩が腰より深く回っているか）、頭が左右に大きく動いていないか、左腕の曲がり
- 切り返し: 下半身（腰）から動き始めているか。上半身だけで打ち下ろしていないか
- インパクト付近: 頭の位置がアドレスから大きくずれていないか、腰の開き、体の沈み・伸び上がり
- フィニッシュ: 最後まで振り切っているか、体重が前足に乗って立てているか、バランスが崩れていないか
- 複数回振っているときは、振りごとに上を見て、ばらつきも書く（素振りと実打は区別する）

## 判断のヒント
- `summary.motion.peaks` / `mountains` の山が各スイングの切り返し〜フィニッシュ。山の前後 0.5 秒のキーフレームを必ず見る。ゆっくりした素振りは山が低いこともある
- 山が複数あるときは、山どうしの間隔でスイングの回数を数え、時刻を `m:ss` で書く
- `mainPersons` が 1 人ならその人。複数映っていたら、一番大きく映る人をゴルファーとする（id は入れ替わるので位置と大きさで追う）
- 頭や肩・腰の位置の変化は keypoint（頭 0、肩 5/6、腰 11/12）の座標の時系列で補強してよい。ただし画像と矛盾したら画像を優先する
- 利き手（右打ち・左打ち）と、横から見ているか正面かは、画像で先に確かめる

## レポートの形式
1. 概要（ゴルファーの特徴を 2〜3 文）
2. 良い点（最大 3 つ。時刻と根拠つき）
3. 直す点（最大 3 つ。優先度の高い順。時刻・何が起きているか・次の練習で意識すること）
4. スイングごとのメモ（複数回あるときのみ。`m:ss` つきの短い箇条書き）
5. 判断できなかったこと

`result.json` の `findings` は「良い点」「直す点」を 1 件ずつ入れ、`title` の頭に `[良]` か `[直]` を付ける。

## 注意
- ボールとクラブは追跡しない。クラブの軌道（インサイドアウト等）、フェース向き、球筋、飛距離は書かない
- 骨格は 2D で、約 10fps。インパクトの一瞬は間のコマに落ちることがあり、横からだと腕や肩が重なって潰れる。細部は画像で確かめ、確かめられなければ「判断できない」と書く
- 角度などの数値の目安を、画像や計測で確かめずに書かない
- 道具・ウェア・コースの話はしない
