# 子どもの運動会・発表会の解析（大勢の中の 1 人を追う）

## 目的
大勢が映る運動会（かけっこ、ダンス、組体操など）や発表会の動画で、わが子 1 人の動きを追い、
どの場面でどんな動きをしていたかを、思い出として読める形でまとめる。上手い下手の採点はしない。

## 追う人（ここを毎回書き換える）
- 例: 赤い鉢巻・白い体操服、前から 2 列目の左から 3 人目。ダンスの途中で後列に移る
- 例: 青のゼッケン 5 番。かけっこでは内側から 2 番目のコース
- 画面上の位置、服装、帽子や髪型を、できるだけ具体的に書く。書かないと追えない

## 見る観点
- 見つけた場面: 追う子が映っている時間帯（`m:ss`〜`m:ss`）と、映っていない（隠れた・画面外の）時間帯
- 動き: 走る・踊る・並ぶ・待つのうち何をしているか。動きが大きい場面と、止まっている場面
- 周りとの関係: 周りの子と同じ向き・同じタイミングで動いているか（ダンスや組体操の場合）
- よく出来た場面、楽しそうだった場面（表情が分かるときだけ）

## 判断のヒント
- 大勢が映る動画では `mainPersons` は信用しない。人が多いと id が大量に割れ、主な人物は「映っていた割合が大きい別の誰か」になりやすい。
  `minorPersonIds` にわが子がいることもある。id は最初の手がかりにとどめる
- 追う子は、キーフレームと一覧画像（`summary.sheets`）を見て、画面上の位置・服装・髪型で決める。見つけた時刻の周りで、骨格の id が合っているかを確かめる
- 途中で位置が変わる（列が動く、隊形が変わる）ときは、前後の画像で同じ子かを確かめる。確信が持てないときは書かない
- 画面が揺れる、ズームする、他の人の影に入る場面では追えない。そのときは時刻を書いて「追えなかった」にする
- 動きの山（`motion.peaks`）は全員の動きの合計なので、わが子だけの動きの目安にならない。山は場面の区切りとして使い、わが子の動きは画像で見る

## レポートの形式
1. 概要（どんな競技・演目で、わが子がどの辺りに映っていたか 2〜3 文）
2. 場面ごとのメモ（`m:ss` つきの時系列の箇条書き。追えた・追えなかった場面を区別する）
3. 良かった場面（最大 3 つ。時刻と、何が良かったか）
4. 追えなかった・判断できなかったこと

`result.json` の `findings` には、場面ごとの要点を `t` つきで入れる。

## 注意
- 人物の特定は、指示書の「追う人」と画像の見た目だけで行う。顔認識はしない。似た服装の子が複数いるときは「断定できない」と書く
- 骨格は 2D で約 10fps。遠くて小さい人（画面の高さの数分の一）や、重なる人は骨格が取れない。取れていない場面を骨格で語らない
- 他の子の評価、優劣の比較はしない。集団の中の 1 人として見る
- 数値（速さ、順位）は、画像や計測で確かめずに書かない
