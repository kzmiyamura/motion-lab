# ソロのダンスの振り付けの解析

## 目的
1 人が音楽に合わせて踊る動画で、振り付けの流れ（どの動きがいつ来るか）と、
音楽の拍に対する動きのタイミングを、練習で覚え直せる形で書く。

## 見る観点
- 動きの区切り: 動きの山・静止（止め）で区切り、振りを順番に並べる。各区切りの時刻と、動きの特徴（腕・脚・体の向き・移動）を書く
- 拍とのずれ: 大きな動きや止めが拍の上に乗っているか、毎回少し前（走る）・後ろ（遅れる）にずれていないか
- 繰り返し: 同じ振りが複数回出るとき、毎回同じ形・同じ大きさか。回を重ねての崩れ
- 軸とバランス: ターンや片足のあとにふらついていないか、上半身の高さ・向きが揃っているか
- 見せ方: 動きの大小のメリハリ、止めがきれいに止まっているか

## 判断のヒント
- `summary.beatGrid` があれば `{bpm, firstBeatSec, beatIntervalSec}` から拍の時刻（`firstBeatSec + n × beatIntervalSec`）を計算し、`summary.motion.peaks` の時刻と比べる。
  ピークが拍の何割前後にあるかを書き、ずれは拍の間隔に対する割合で言う（0.1 秒より小さいずれは 10fps では決められない）
- `beatGrid` が null のとき（`beatGridReason`: `silent` は音なし、`unclear` はリズム不明瞭）は、拍の話をせず、動きの区切りと繰り返しだけを書く。その理由をレポートの最後に書く
- 拍の頭か裏か、8 カウントのどこかは、拍の位置だけでは分からない。曲の構成は画像と曲から分かる範囲だけ書き、分からなければ書かない
- 動きの山は 1 つの振りの中に複数ある。`mountains` の区間を振りのまとまりの目安にし、キーフレームと一覧画像（`summary.sheets`）で形を確かめる
- 映っている人が複数なら、`mainPersons` の一番大きい人を踊り手とする。鏡の像は `minorPersonIds` に入りやすい

## レポートの形式
1. 概要（振りの雰囲気・長さ・BPM を 2〜3 文）
2. 振りの流れ（`m:ss` つきの時系列の箇条書き）
3. 拍とのタイミング（ずれの傾向。拍が取れなければ「取れなかった」）
4. 直す点（最大 3 つ。優先度の高い順。時刻・何が起きているか・次の練習で意識すること）
5. 判断できなかったこと

`result.json` の `findings` には、振りの流れの要点と、直す点を入れる。

## 注意
- 骨格は 2D で、約 10fps。指先・手首の細かい動きや、速い足さばきは捉えられない。細部は画像で確かめ、確かめられなければ「判断できない」と書く
- 拍は音声から取った推定で、BPM がずれる（倍・半分）ことがある。曲を知っているなら、レポートの数字が合うか本人が確かめる
- 振りの名前（技名）や、正しい振りとの一致は、指示書に書かれていない限り判定しない
- 衣装・背景・撮影の話はしない
