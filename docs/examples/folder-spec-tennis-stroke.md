# テニスのストローク・サーブの解析

## 目的
プレーヤー 1 人を、ラリーやサーブ練習の中で撮った動画で、ショットごとのフォームの崩れと、
ショットどうしのばらつきを、本人が次の練習で直せる形で伝える。

## 見る観点
- 準備: ラケットを引くのが早いか、肩の向き（体を横に向けているか）、スプリットステップ後の構え
- 足の運び: 打つ前に足が止まっているか、踏み込みの向き、体重移動
- 打点付近: 体と打点の距離、頭が残っているか、体が開くのが早すぎないか
- フォロースルー: 最後まで振り抜いているか、フィニッシュ後にすぐ構えに戻れているか
- サーブ: トスの腕の高さと位置、トロフィーポーズの膝の曲げ、打ち上げる伸び、着地の姿勢
- ショットが複数あるときは、ショットごとに上を見て、ばらつきと、疲れてきたときの崩れも書く

## 判断のヒント
- `summary.motion.peaks` / `mountains` の山が各ショットのだいたいの瞬間。ラリーでは山が打球ごとに並ぶ。山の前後 0.5 秒のキーフレームを必ず見る
- 山の間は移動や待ちで、山が低くてもショット（軽い当て方）のことがある。山が少ないときは、一覧画像（`summary.sheets`）で並べて確かめる
- フォアかバックか、サーブかは画像で確かめる。時刻とあわせて「0:12 フォア」のように書く
- 相手や球出しの人が映るときは、`mainPersons` から、フォームを見たい人を画面上の位置（手前・奥、コートの側）と服装で決める。id は入れ替わるので追い直す
- 速い動きは 10fps だと間が空く。山の頂上の 1 コマだけで決めず、前後のコマも見る

## レポートの形式
1. 概要（プレーヤーの特徴を 2〜3 文）
2. 良い点（最大 3 つ。時刻と根拠つき）
3. 直す点（最大 3 つ。優先度の高い順。時刻・何が起きているか・次の練習で意識すること）
4. ショットごとのメモ（`m:ss`、種類つきの短い箇条書き）
5. 判断できなかったこと

`result.json` の `findings` は「良い点」「直す点」を 1 件ずつ入れ、`title` の頭に `[良]` か `[直]` を付ける。

## 注意
- ボールとラケットは追跡しない。ボールの行き先、スピン、ラケット面の向き、ミスヒットの理由は、画像で見えない限り書かない
- 骨格は 2D で、約 10fps。インパクトの瞬間は捉えにくく、後ろや横から撮ると腕が体に隠れる。見えないものは「判断できない」と書く
- 距離や角度の数値は、画像や計測で確かめずに書かない
- 勝敗、戦術、相手の評価はしない
