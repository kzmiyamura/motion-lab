# 筋トレ・ストレッチのフォームの解析

## 目的
スクワット・腕立て伏せ・ランジなど、同じ動きを繰り返す種目を撮った動画で、
回数と、回を重ねたときのフォームの崩れを、次のセットで直せる形で伝える。

## 見る観点
- 回数: 何回行ったか。数えた根拠（各回の時刻 `m:ss`）を書く
- 1 回の動き: しゃがむ深さ（腿がどのくらい下がるか）、膝がつま先と同じ向きに曲がるか（内側に入らないか）、背中が丸まらないか、かかとが浮かないか
- 左右差: 左右の肩・腰の高さ、体重が片側に寄っていないか
- 崩れ: 後半の回で、深さが浅くなる、速さが落ちる、上体が前に倒れるなどの変化
- ストレッチは、保持中に体が揺れていないか、姿勢が保たれているか、伸びている方向

## 判断のヒント
- `summary.motion.peaks` / `mountains` の山が 1 回ごとの動き（下げて上げる）に当たる。山の数を回数の候補にし、キーフレームで 1 回ずつ確かめる。
  山の間隔が不規則なときや、休憩・直しを挟むときは、その時刻を書いて数えない
- 山の高さ（動きの大きさ）が後半で小さくなっていれば、速さや深さの低下の手がかりになる。ただし胴の長さ/秒の相対値なので、画像で確かめる
- しゃがんだ底（山と山の間）のキーフレームに、深さ・膝・背中の形が出る。ここを必ず見る
- 腰・膝・足首（keypoint 11〜16）の座標の時系列で、深さの変化を数値で補強してよい。真横でないと膝の向きや背中は決められないので、撮影の向きを画像で先に確かめる
- 映っている人が複数なら、`mainPersons` の一番大きい人をやっている人とする

## レポートの形式
1. 概要（種目、回数、撮影の向きを 2〜3 文）
2. 良い点（最大 3 つ。時刻と根拠つき）
3. 直す点（最大 3 つ。優先度の高い順。何回目の何が起きているか・次のセットで意識すること）
4. 回ごとのメモ（崩れが出た回だけ。`m:ss` つきの短い箇条書き）
5. 判断できなかったこと

`result.json` の `findings` は「良い点」「直す点」を 1 件ずつ入れ、`title` の頭に `[良]` か `[直]` を付ける。

## 注意
- 骨格は 2D で約 10fps。真横以外の角度では、深さ・膝の向き・背中の丸まりは正確に決められない。確かめられないときは「判断できない」と書く
- 器具（バーベル・ダンベル）は追跡しない。重さ、バーの軌道、負荷の強さは書かない
- 痛み・怪我、医学的な判断はしない。気になる形は「フォームの観点で」と書く
- 角度や深さの数値の目安を、画像や計測で確かめずに書かない
